# FunPay — этап 1: запрос ссылки и её сохранение

На этом этапе реализованы:
- подключение к аккаунту FunPay через неофициальную библиотеку `MorikTV/FunPayAPI`;
- обнаружение новых оплаченных продаж;
- отправка сообщения от имени продавца с просьбой прислать ссылку;
- получение одной ссылки в чате и её сохранение;
- очередь заказов одного покупателя, чтобы не перепутать ссылки;
- база SQLite в `/app/data/bot.db`;
- восстановление ещё активных оплаченных заказов после перезапуска.

Vexboost и Telegram-бот администратора пока не подключены.

## 1. Подготовка проекта на хостинге

Требуется Python 3.10+ и Git.

Установите зависимости:
```bash
pip install -r requirements.txt
```

Загрузите библиотеку FunPay в корень проекта:
```bash
bash scripts/install_funpay_api.sh
```

После выполнения рядом с `main_funpay.py` появится папка `FunPayAPI/`.

Если хостинг не позволяет выполнять Git-команды, скачайте исходную папку `FunPayAPI` из
https://github.com/MorikTV/FunPayAPI и загрузите её в корень проекта через файловый менеджер.

## 2. Переменные окружения

Создайте переменные в панели хостинга:

```env
FUNPAY_GOLDEN_KEY=ВАШ_GOLDEN_KEY
FUNPAY_USER_AGENT=ВАШ_USER_AGENT_ИЗ_БРАУЗЕРА
FUNPAY_REQUESTS_DELAY=8
FUNPAY_DRY_RUN=true
FUNPAY_FIRST_START_BASELINE=true
DATABASE_PATH=/app/data/bot.db
```

`golden_key` — секрет доступа к аккаунту FunPay. Никому его не отправляйте, не вставляйте в исходники и не публикуйте в логах.

User-Agent лучше скопировать из того же браузера, где вы вошли в FunPay. Не передавайте его вместе с ключом в публичных местах.

## 3. Постоянная база данных

Путь совпадает с инструкцией хостинга:
`DATABASE_PATH=/app/data/bot.db`

Каталог `/app/data` создаётся автоматически. Он должен быть постоянным (persistent volume) и доступным контейнеру на запись. Не добавляйте каталог `data` в Git.

## 4. Первый безопасный запуск

Оставьте:
`FUNPAY_DRY_RUN=true`

Команда запуска:
```bash
python main_funpay.py
```

В этом режиме программа:
- авторизуется в FunPay;
- получает текущие продажи;
- запускает мониторинг событий;
- распознаёт новые оплаченные заказы;
- записывает заказы в SQLite;
- показывает в логах, какое сообщение отправила бы покупателю;
- НЕ отправляет сообщения и НЕ трогает Vexboost.

При первой установке старые продажи отмечаются как базовые и не получают автоматических сообщений. При следующих запусках программа восстанавливает новые неоплаченные/активные продажи, пропущенные при перезапуске, если они всё ещё имеют статус `PAID`.

## 5. Включение реальной отправки сообщений

Сначала убедитесь по логам, что:
- аккаунт FunPay определился правильно;
- новый тестовый оплаченный заказ попал в логи;
- ID покупателя, название лота и количество читаются корректно;
- база создаётся по пути `/app/data/bot.db`.

Затем поменяйте:
`FUNPAY_DRY_RUN=false`

Перезапустите процесс. С этого момента программа будет отправлять покупателю сообщение:

«Здравствуйте! Спасибо за заказ #ID.
Услуга: НАЗВАНИЕ
Количество: N

Отправьте, пожалуйста, ссылку на публикацию одним сообщением.»

Покупатель должен отправить одну полную ссылку HTTP(S). На этом этапе ссылка сохраняется в SQLite, но заказ в Vexboost ещё не создаётся.

## 6. Как работает очередь

Если один покупатель купил несколько лотов:
- бот отправит запрос ссылки только для первого заказа;
- после получения ссылки сохранит её;
- затем запросит ссылку для следующего заказа.

Старые сообщения до отправленного запроса ссылки игнорируются: сохраняется ID сообщения, которым бот запросил ссылку.

## Ограничения и предосторожности

- FunPay не предоставляет публичный API продавца; библиотека использует внутренние механизмы сайта и может перестать работать после изменений FunPay.
- Автоматизация должна соответствовать актуальным правилам FunPay. Использование неофициальной библиотеки может нести риск ограничений аккаунта.
- Если FunPay недоступен, бот продолжит попытки с задержкой; проверяйте логи.
- Если хостинг перезапускает контейнер и не сохраняет `/app/data`, история заказов потеряется. Нужен именно постоянный диск.
- В редком случае аварии между успешной отправкой сообщения и записью ID отправленного сообщения возможна повторная просьба ссылки после рестарта.
- Детальная проверка допустимого домена ссылки и сопоставление конкретного лота с ID Vexboost добавляются на следующем этапе.
